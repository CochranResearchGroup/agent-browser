# Agent Browser

Agent Browser coordinates browser automation and operator-visible remote control while separating access authority, work coordination, and exact runtime lifecycle ownership.

## Language

**Task operation receipt**: Existing-owner evidence for one original addressed
CDP request, retained before transport. Attempt, owner acknowledgement and site
completion are separate. Readback never dispatches; Native/Auth journals retain
their own authority.

**Candidate revision**: An immutable SiteGuide child in the existing directory,
preserving parent, source and operation lineage while accepted versions remain.

**Teaching review receipt**: A receiver-owned, attributable explicit operator
decision bound to task, root and exact file/content digests, reverified on reopen.
It does not establish fresh-repeat execution qualification.

**Evidence availability**: Per-reference owner-bound access, distinct from overall
recording access and retention of the accepted procedure.

**Teaching draft**: Inert source-linked teaching knowledge in an existing
SiteGuide candidate. The agent interprets video/narration into parameters,
routines and a composed playbook before focused questions. Inspection validates
shape and source references, not factual truth, approval or successful execution.

**Teaching evidence**: Exact finalized A/V recording and selected isolated
narration linked to Speech Saved/range receipts. Gaps, conversion alignment,
speaker identity and critical-token uncertainty remain explicit; a sequence
annotation does not verify recorder suppression.

**Task briefing**: A read-only exact-ID projection of retained goal attribution,
current logical identity, historical verified progress, local artifact references,
pending assistance/control and original uncertain operations. It never launches,
observes a live page, acknowledges human use or turns missing evidence into success.

**Browser mode inspection**: Read-only current original-process debugging posture.
CDP and no-CDP require complete current process evidence joined to immutable
owner identity. Missing, changed or stale evidence is unverified. Executable
name/family, native input readiness, viewer delivery and authentication remain
separate observations; inspection does not acquire or mutate a browser.

**Inspection review**: An explicit accepted or rejected judgment about one frozen inspection run, scoped to its original workspace, task, browser, tab and profile. Activity retains bounded identity and evidence-reference metadata. The judgment does not change observation validity, execution authority or readiness.

**Exact task routing**: MCP page commands and authenticated dashboard browser
operations retain task identity and resolve the transport lane separately.
A named dashboard command uses the existing owned session route; an unavailable
owner is reported without falling back to the dashboard backend. The managed host joins the exact ID
to the task name and selected browser profile. Missing or conflicting identity
cannot fall back to another same-name task or a fresh launch.

**App browser attachment**: Borrowing an exactly observed app process, canonical
profile and existing page while Agent Browser supplies task operations. Initial
page census remains app-owned; attachment grants no termination or relocation.
Explicit sharing admits exact app participants to distinct logical tasks without
changing the process owner.

**Cooperative human control**: Durable browser-scoped ownership and epoch shared
by supported dispatch routes. Viewing alone changes nothing. Explicit takeover
blocks new mutations, optionally reads/capture; return freshly observes the same
page. Dispatched uncertainty is retained without replay. Unmanaged controllers
must cooperate; attribution is separate from operator authority.

**Routine interlock output**: Bounded status/error projection for scheduled
maintenance. It is distinct from the private latest-pass monitor receipt and
explicit detailed JSON. Logging mode does not change maintenance authority,
failure exits, or cleanup qualification.

**Browserless handoff preparation**: A daemon with no attached browser returns
`prepared=false`, `browserPresent=false` and no candidate. This is a local
observation, not proof that shared-host browsers or uncertain effects are
absent. Preserve retained evidence and inspect the existing preserve-mode
workstation transaction before retrying.

**Embedded Native page evidence**: A prepared handoff, a readable viewer document and an authenticated Native display connection are separate observations. An unreadable frame may be an access redirect or a framing restriction; it does not prove expired authentication. A readable non-viewer page is unavailable for embedding without establishing why.

**Subsystem health evidence**: Separately scoped inventory availability, runtime diagnostic readiness, Native slot readiness and observed selected-view connection state. Unchecked, stale, timed-out or malformed evidence is unverified. Service reachability and handoff preparation do not prove display delivery.

**SiteGuide**: Versioned knowledge for recognizing a website's states, locating
controls, interpreting results and verifying an intended outcome. Site knowledge
is separate from the selected account and its credentials.

**Routine**: A reusable executable subtask with declared inputs, expected state,
result and effect semantics.

**Playbook**: A composition of routines to reach a website goal. Software, an
agent, or a combination of both can choose the next routine.

**Automation skill**: Guidance for choosing routines and adapting to unexpected
website states using the same SiteGuide and routine contracts as software.

**Hosted caller identity**: The ordinary attested work/thread requesting an
existing hosted authentication helper operation. It is distinct from the
receiving browser task and requires no Bots roster enrollment.

**Receiving browser binding**: The frozen provider, task, profile, browser and
tab tuple where a hosted authentication request may act. The same request
preserves that binding across interruption and independent readback.

**Current protected-field emptiness**: Trusted current evidence that protected
controls are empty, combined with independently verified clean-login/native
safety. It may release capture after a failed attempt, but never erases input
history, proves authentication, renews expiry or authorizes replay.

**Host memory reserve**: Available memory kept for other work and recovery when
admitting a new browser process. Reusing an existing browser does not allocate a
second process. Pressure handling preserves current work.

**Terminal history projection**: The recent completed session and tab records
kept with active browser state. Bounding this projection does not delete older
durable history or change live tasks and valid handoffs.

**Manual login mode**: A managed Native window with no CDP endpoint, debugging
listener or DOM control. Authorized agents can observe screenshots and send
Native input when the exact process, window and provider are ready. Human
takeover is a separate control-authority choice. The mode owns one logical task
and preserves its durable profile; its URL describes initial intent, not the
current page or verified authentication.

**Mode conversion**: An explicit owner operation that replaces a physical
browser with or without CDP while preserving its logical task, profile and
original handoff. It reviews affected tasks and consequential close choices;
ordinary open never silently changes a running process's posture. Transient
page state may be lost, and uncertain website submissions are never replayed.
Source or synthetic qualification does not prove installed Native readiness or
authenticated site state.

**Browser operation lookup**: Read-only discovery of retained owner mode-conversion
or profile-copy operations for an exact task, browser and profile scope. Reload
and selection read the original operation ID and supported actions without
launching, closing or copying. Multiple matching copies require selection;
a conflicting operation returns its original locator. Private profile paths
and credentials stay outside public summaries and client persistence.

**Durable profile**: Browser data retained across tasks. Separate tasks can share its browser through distinct sessions and tabs. Profile retention is separate from process, desktop, session and handoff lifetimes.

**Workspace inventory projection**: The redacted managed-owner inventory with
bounded native window and exact CDP observations used by the default dashboard.
It does not wait for service reconciliation or workstation diagnostic scans and
does not grant automation or viewing authority. An explicitly selected current
task may request authoritative handoff verification while descriptive presence
is unknown; only the successful exact live focus makes its viewer ready.
Existing-tab operator handoff uses the shared browser owner directly without a
legacy HTTP launch lane or scheduler job; signed focus and desktop ordering
still gate the effect.

**Handoff link lifetime**: The configurable period during which a handoff link can be used. The default is perpetual. Link expiry does not end the target tab or delete the link record.

**Tab lifetime**: The independent, configurable retention of a task's tab. An unused human handoff can protect its tab according to the pending-human retention policy. Ending one tab preserves its peers; the browser closes when its last live tab ends.

**Handoff link deletion**: Explicit revocation of a handoff link, separate from its lifetime and its target tab's lifetime. It does not close the target tab or browser.

**Handoff target recreation**: Opening a still-valid link recreates its expired target tab from retained target metadata in an eligible browser, or wakes a browser as needed. This restores target access rather than promising recovery of lost in-memory page state.

**Pending-human retention**: Configured protection for a handed-off tab before confirmed human use. Its duration and pressure policy are independent of link validity; four hours is an example configuration value rather than a fixed timeout. Explicit human handoff production prepares this protection; ordinary agent work and readiness resolution do not consume it. Successful human use requires the native provider to qualify an authenticated connection, a delivered display frame and its matching acknowledgement. The browser owner joins that evidence to the current exact handoff/tab/target before consuming the hold. Readiness and redirects preserve retention; tab inactivity resumes after qualified use.

**Pressure inactivity**: An opt-in threshold on each live tab, independent of ordinary tab lifetime and link validity. Disposable count and byte quotas can retire a browser only when every live target is eligible and current activity authority permits it. Link deletion does not make peer work eligible. Broader host resource governance remains a separate program.


**Disposable profile**: Browser data allocated for temporary work and eligible for configured inactivity cleanup only after required references are released.

**Leave-open close**: Preserves the managed task and its live browser for continuation, including across host restart and idle cleanup. It retains occupied profile custody. Explicit `--leave-open false close` ends the task; a full-shutdown operation overrides the preference.

**Ready spare desktop**: A usable vacant desktop prepared for the next independent browser. Maintain one when capacity permits; wrap-around handles overflow, and configurable cooldown retires excess unused desktops.

**Development publication**:
An isolated generation installation whose activation coordinates the runtime host and dashboard process group. Non-activating publication requires stopped units before changing executable bindings. Host retirement preserves retained browser children and persistent private temporary storage.


**Client subject**:
The stable identity to which access policy grants are assigned, together with an explicit assurance level such as locally self-declared or authenticated.
_Avoid_: Runtime owner, daemon identity, session name

**Connection instance**:
The service-generated identity for one live attachment of a Client Subject, used for command attribution and temporary coordination without becoming durable access authority.
_Avoid_: Client ID, principal, browser session

**Access policy**:
The revisioned rules that authorize a Client Subject to observe, use, coordinate, administer, or reclaim a browser resource.
_Avoid_: Lease, runtime ownership proof, profile identity

**Lease-authority kernel**:
The singular authority for active resource claims, monotonic revisions, fencing tokens, and effect authorization. Historical events, terminal records, and projections describe prior outcomes but never become current authority.
_Avoid_: Access policy, Service State lease, runtime ownership proof

**Shared-local profile**:
A profile whose default policy allows locally trusted Client Subjects to reuse one managed browser and receive attributable tabs without first enrolling a strict identity.
_Avoid_: Unowned profile, public profile, exclusive profile

**Policy revision**:
The monotonic version of one Access Policy against which an admission, denial, or policy edit is evaluated.
_Avoid_: Owner generation, lease generation

**Profile occupancy**:
The current set of client work, tabs, controller leases, and viewer leases that must be considered before a profile can become more restrictive.
_Avoid_: Profile ownership, process ownership

**Drain-and-restrict transition**:
A revision-fenced change that stops new admission, clears incompatible Profile Occupancy, and commits a narrower Access Policy only after the required occupancy reaches zero.
_Avoid_: Immediate revocation, force unlock

**Eviction authority**:
The explicit permission to end another Client Subject's current Profile Occupancy during a Drain-and-restrict Transition.
_Avoid_: Policy edit, lease release, process kill

**Runtime ownership proof**:
Internal evidence that binds an exact managed browser or runtime process to its profile, executable, process instance, endpoint, and owner generation before lifecycle effects occur.
_Avoid_: Client identity, access permission, profile lease

**Browser launch custody**:
The durable intent and observed process evidence for one browser launch, bound to
an exact profile and desktop assignment. An unresolved intent blocks another
launch or recovery for that profile while unrelated profiles continue through
their own custody and assignment-generation checks. Native cold-launch path and
capacity preflight precedes durable intent; failure there creates no process
claim. Failure after intent admission still requires exact reconciliation.
The launch observation optionally freezes the original kernel start identity.
Capture is tied to the unreaped launched child or verified profile attachment;
restart reads immutable custody instead of filling missing evidence from a live
PID. Missing legacy evidence stays missing. Its first durable observation
atomically promotes the database reader version. Retirement use of this evidence
still requires separate effect and readback qualification.
_Avoid_: Global runtime lock, browser readiness, profile access policy

**Native idle retirement fence**:
The provider's durable exclusion of new native viewer admission during one
exact application retirement operation. Its monotonic slot revision and
operation digest prevent stale requests from borrowing another operation.
A typed observation or prepared receipt is not browser-close authority.
Application custody must precede preparation and retain unknown effects;
neither a timeout nor dropping a local guard settles the native fence.
The automatic-close candidate joins this fence to application custody; source
sequencing tests remain separate from native workflow and installed acceptance.

**Browser activity reservation**:
A passive Runtime SQLite veto on automatic retirement of an admitted command's
published root. Admission and retirement serialize in one writer transaction.
Successful command acknowledgement retains the veto until session publication
removes it atomically. An unknown effect retains custody, not replay authority.
Reservations require at least reader schema 3. This record owns
neither command results nor tab-creation replay.
Original published kernel evidence is frozen at admission, never backfilled for
legacy rows. Positive original-process exit settles only its resource veto;
unknown command history remains. Evidence and ended-resource settlement require
reader schema 4. Unavailable readback vetoes replacement before launch.

**Idle retirement custody**:
The Browser Runtime's durable exact-baseline intent, native preparation, close
attempts and conclusive settlements. Duplicate attempts require original
readback. Session publication and custody commit together before native fence
completion. The first claim atomically promotes the private database to schema 2
so a schema-1-only reader cannot ignore this obligation.
Pending scopes fence conflicting SQLite publications and launch/recovery
admission in the same writer transaction; unrelated profiles remain usable.
Physical attempt admission reads the current durable record atomically; a
matching generic CAS replay cannot authorize a duplicate close.
Preparation admission also distinguishes one fresh attempt from original
readback. Known preparation with no admitted effects can reconcile through
unchanged-state publication; unknown preparation with no fence cannot.
Browser command delegation checks current durable profile custody before tab
acquisition, creation, navigation, focus and command execution. This check denies
already-pending retirement; it does not yet establish atomic admission against a
concurrent retirement start. Process-liveness observations remain available.
Normal close confirmation distinguishes positive OS absence from observation
failure. An unavailable census retains an unresolved outcome; original-process
identity across PID reuse requires separate evidence.
A new retirement scope copies immutable published launch kernel evidence. Claim
admission verifies that join in its SQLite writer transaction and retains the
frozen value across restart. Admitted runtime effects and target readback use the
frozen scope. A new kernel start may prove the original ended, never authority
over its replacement. Live-target readback attaches only to the verified original
browser; failed observation or missing legacy identity supplies no close authority.
New groups preflight original kernel evidence across every selected assignment
before new claims, native preparation or attempts. Missing legacy evidence defers
without creating obligations; existing unresolved operations retain exact readback.
Native workflow and installed qualification remain separate.

**Request provenance**:
The immutable causal identity carried from ingress through admission, execution, terminal response, job, event, trace, and incident records.
_Avoid_: Log message, caller label, lane selector

**Daemon command**:
A requested browser or control-plane operation executed in the serialized native runtime.
_Avoid_: Action handler, request handler

**Service State**:
The durable authority for managed profiles, browsers, tabs, routes, leases, jobs, and their lifecycle evidence.
Retirement retains shared Service State admission for a coherent snapshot and
an independent exclusive retirement fence for effect serialization. Diagnostic
reads remain available; controller and handoff commits remain fenced. The
retirement fence's owner attribution is distinct from the shared state lock.
_Avoid_: Dashboard state, runtime cache

**Remote-view intent**:
The normalized desired browser, target, route, viewing, and control posture for an operator-visible browser acquisition.
_Avoid_: Remote-view request, open parameters

**Route-bound handoff**:
An operator-visible browser acquisition whose route, display, browser, target, lease, and proof identities agree.
_Avoid_: Remote desktop link, route open

**Acquisition lease**:
The exclusive pending or finalized claim that prevents two acquisitions from owning the same route-bound browser lane.
_Avoid_: Lock, checkout record

**Profile acquisition intent**:
A request by one authenticated service principal to obtain or reuse one managed browser lane for an exact profile and task without choosing internal browser, session, route, or lifecycle identities.
_Avoid_: Launch request, session request

**Profile acquisition owner**:
The deep in-process module that joins current Service State, access policy, coordination evidence, and runtime proof into one executable acquisition decision or exact denial. Service Access, recovery, and action runtime consume this decision and never reconstruct it from JSON or reason strings.
_Avoid_: Access-plan helper, recovery policy, launch policy

**Install convergence owner**:
The Rust module that owns desired workstation state, observed state, the sealed convergence plan, and the terminal receipt. Privileged shell code is an effect adapter and the dashboard consumes the owner's typed readiness result.
_Avoid_: Installer script, doctor warning, dashboard health heuristic

**Workstation writer custody**:
Evidence that one currently executing workstation mutation owns its coordinated operation. Process-start and PID-file identity distinguish that writer from retained diagnostics. Custody follows that process instance even if its executable is renamed or unlinked. Short physical locks protect claim transitions; warnings and historical PID text do not grant or withhold operator authority.
_Avoid_: Live PID alone, upgrade marker, permission grant

**Semantic contract oracle**:
Canonical acquisition and convergence scenarios plus invariants used to prove that HTTP, MCP, generated clients, dashboard projections, and execution admission all represent the same decision.
_Avoid_: Shape smoke, snapshot test, transport fixture

**Dominant blocker**:
The single current fact that determines why a profile acquisition cannot proceed, while all other relevant inconsistencies remain available as supporting evidence.
_Avoid_: Error list, first validation failure

**Recovery plan**:
A sealed, expiring, state-revision-bound proposal for the exact transitions needed to make one inconsistent profile acquisition safe to retry.
_Avoid_: Force unlock, repair script

**Recovery receipt**:
The durable result of checking and applying one Recovery Plan, including its preconditions, effects, compensation, terminal state, and acquisition retry outcome.
_Avoid_: Command log, success message

**Mitigation action**:
One bounded, idempotent, authority-preserving transition owned by the recovery plane and guarded by current evidence.
_Avoid_: Force operation, manual state edit

**Retained browser**:
A browser that remains alive across daemon or route transitions and whose existing ownership must be respected during recovery.
_Avoid_: Orphan browser, stale browser

**Service tab handle**:
The stable service identity that binds a managed tab to its browser, session, and current target evidence.
_Avoid_: Target ID, tab ID

**Operator-visible proof**:
The combined evidence that the intended browser target is visible and reachable through the authoritative operator route.
_Avoid_: URL readiness, route health

**Durable handoff**:
An opaque public identity that can reacquire current route and browser evidence without exposing an ephemeral provider address.
An exact live session/tab binding retains that session through inactivity until explicit closure or lifecycle failure; a dangling historical binding confers no retention or access authority.
_Avoid_: Guacamole URL, provider URL

**Desktop evidence episode**:
A bounded observation or interaction transaction that owns evidence selection, presentation admission, scene proof, capture, verification, restoration, and release for one browser workspace.
_Avoid_: Desktop screenshot request, capture mode

**Presentation slot**:
Scarce operator-visible desktop capacity binding one route, display, current scene, human posture, readiness generation, and cleanup obligation without owning the retained browser lifecycle.
_Avoid_: Route, virtual desktop

**Warm presentation pool**:
The ready minimum of presentation slots retained for low-latency human, recovery, and desktop-evidence admission while elastic slots may be added or reclaimed within pressure limits.
_Avoid_: Two-route pool, fixed desktops

**Capture-ready proof**:
Fresh evidence that the exact authorized browser scene is staged, topmost, maximized or at approved geometry, unoccluded, and still bound to its route, display, process, viewer, controller, and geometry identities.
_Avoid_: Browser visible, route ready

**Runtime environment**:
An isolated installation authority that owns one executable selector, generation store, runtime state root, socket namespace, supervisor identities, dashboard and authentication state, port allocation, provider namespace, garbage-collection scope, and acceptance receipts.
_Avoid_: Install mode, alternate port

**Development runtime**:
A non-production Runtime Environment for experimental builds whose installation, execution, validation, and reclamation cannot select, restart, mutate, or claim acceptance for the production Runtime Environment.
_Avoid_: Debug binary, staging flag

**Build admission**:
A bounded claim on current host compilation capacity derived from memory, swap, CPU, disk, active build claims, and configured reserves.
_Avoid_: Cargo lock, unlimited parallel build

**Environment receipt**:
Evidence that binds an installation, process, dashboard, ingress, validation, or cleanup result to exactly one Runtime Environment identity.
_Avoid_: Install log, shared status

**Provider fallback**:
A best-effort retained-route outcome that preserves an existing browser without claiming normal managed control or creating another ownership lane.
_Avoid_: Successful reopen, automatic recovery

**Forward deadline**:
The route-bound open deadline for new effects, computed from the existing total job timeout after reserving bounded time for compensation.
_Avoid_: Operation timeout, extended timeout

**Compensation reserve**:
The final portion of the existing total job timeout available only to undo effects that the coordinator recorded as completed. It does not extend the public deadline.
_Avoid_: Cleanup timeout, grace period

**Scripted runtime**:
A deterministic test implementation of the route-bound runtime seam that records invoked effects and advances a fake clock without browser or live runtime effects.
_Avoid_: Mock browser, integration runtime

**Coordinator-owned completion**:
The worker signals timeout or cancellation through the route-bound token and retains the coordinator future until bounded compensation reports a terminal state.
_Avoid_: Post-timeout join, background cleanup

**Rollback quarantine**:
A terminal fail-closed acquisition record used when compensation cannot confirm every owned external effect before the total deadline. It removes active checkout and blocks an equivalent acquisition until explicit recovery.
_Avoid_: Partial rollback, cleanup warning

**Concrete owner module**:
A cohesive native module that owns a domain invariant and the operations that preserve it. Command dispatch and peer workflows import this owner directly.
_Avoid_: Action bucket, handler collection

**Runtime host**:
The singular active authority that executes daemon commands for all runtime lanes in one user installation.
_Avoid_: Per-session daemon, session process

**Runtime lane**:
A logical serialized command and ownership scope for one named browser session within the runtime host.
_Avoid_: Daemon instance, socket process

**Cleanup obligation**:
The durable duty to preserve a valid retained resource or reclaim it after its lifecycle becomes terminal.
_Avoid_: Best-effort cleanup, drop behavior

**Reclaimable runtime resource**:
A package-owned process tree, profile, display helper, transaction payload, or runtime generation whose lifecycle is terminal and which has no active ownership, lease, handoff, rollback, or process reference.
_Avoid_: Old resource, orphan

**Runtime convergence window**:
The bounded upgrade interval during which the old and candidate runtime generations may coexist while ownership transfers and rollback remains possible.
_Avoid_: Mixed steady state, maintenance mode

**Transitional facade**:
A temporary re-export-only module used while callers migrate to concrete owners. It is not an architectural owner and must be deleted before the final architecture gate.
_Avoid_: Compatibility owner, permanent facade

**Cohesive green checkpoint**:
A durable commit that binds one interdependent remediation invariant to its focused validation and rollback boundary. Plan 0106 uses these checkpoints instead of reconstructing retroactive one-commit-per-responsibility history; the 615-record responsibility and packet ledger remains intact.
_Avoid_: Retroactive packet commit, grouped unvalidated change

**Native desktop demand**:
A new browser's need for a free Remote View desktop. Pool preparation keeps the configured warm minimum and acquires additional assignments only when observed desktops are occupied, bounded by provider policy. Sessions reusing one profile reuse its browser and desktop.
_Avoid_: Session count, eager maximum reservation, presentation slot

**Graceful host restart**: The exiting host removes authentication metadata only while it owns the endpoint and matching token. Ordinary commands on an existing managed task check and attach its recorded live browser before using its tab, including headless named sessions. Physical recovery stays with the existing fenced owner.

**Supplied tab task metadata**: Original creation context belongs to the actual tab and its recoverable target capsule. Descriptive service, agent, human, origin, task, purpose and request/job labels are explicitly supplied, never identity proof. Unknown attribution stays unknown. Agent-facing MCP task creation requires service, agent and concrete task labels and records its known agent origin. CLI and queued remote-view task creation require those labels and an explicit origin before effects; a local or authenticated principal does not substitute for descriptive context. Dry-run planning and sharing an exact existing target preserve original context. Inspecting or changing link lifetime does not replace creation context. Properties shows recorded creation time independently of attribution and recovers original context only from the same retained logical tab. Profile display names are mutable; stable profile IDs and data directories are not renamed. One-way promotion moves a disposable profile into the durable catalog atomically with removal from disposable cleanup eligibility. Normal browser and tab idle lifetimes remain separate.

**First human use**: A durable first-human-use timestamp follows provider-qualified native viewer use joined to the current exact handoff/tab/target and native focus, independently of originating attribution. Agent readiness or rejected context cannot establish it, and duplicate acknowledgement cannot advance it. Opening a prepared human handoff consumes its pending hold through the same qualified owner operation. Native/HTTP acceptance remains distinct from owner fixture qualification.

**Native handoff observation**: Private continuation context joins one handoff/tab/target to the provider assignment and lifecycle/viewing generations without granting access. Registration intent survives owner restart. Pending and expired observations do not establish use; replay cannot advance the first-use timestamp. A new pending-human hold invalidates old observation bindings, and a changed provider epoch requires fresh registration through the same durable link.

**Clarification question**: An unresolved source-linked material choice whose
prerequisite answers must be verified before it is ready to ask.

**Clarification answer**: A receiver-authenticated event bound to the exact
question and candidate digests. It is independent of procedure approval;
unverified answer history blocks further rounds without inventing consent.

**Download source proof**: A currently verified local browser process and endpoint.
A qualified attachment retains its original PID/start/executable proof for live
revalidation; that proof grants no child-process lifecycle ownership.

**Fresh-repeat receipt**: An existing receiving-application verifier's proof for
an exact executed candidate/task, requested dates, report and actual artifact.
Its verification assertions are independently read, not supplied as request labels.

**Teaching promotion**: An immutable same-store lineage step selected only after
revalidated operator review and fresh-repeat proof. Previous accepted bytes remain;
stock MCP treats saved promotion metadata as inert.


**Native image evidence clock**: Owner-minted Linux elapsed readings bound to the producer and receiver's exact boot. Image age and the first immutable round deadline use this domain; wall timestamps remain diagnostics. Later rounds cannot renew the deadline, change domain, cross boots or fall back to wall time after qualification fails. Legacy receipts and unsupported platforms retain their strict wall-clock guards. Client receiving timers use elapsed time; a projected wall deadline is not input authority.
