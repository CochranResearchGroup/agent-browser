## Operative rules

- Keep one primary owner for Service State, Cargo manifests, architecture decisions, and acceptance.
- Batch one coherent causal group before invoking Cargo and retain compact compiler evidence.
- Preserve the frozen replacement contract and do not restore, rename, or relocate legacy authority.
- Treat commits as custody checkpoints rather than turn boundaries.
- Optimize this milestone for total token efficiency with balanced wall-clock progress; delegate only independent bounded lanes whose expected gain exceeds setup and reconciliation cost.
- Give each worker a compact self-contained packet with no inherited conversation turns by default, an exact write scope, deterministic acceptance check, per-lane allowance, and semantic stop condition.
- Admit workers sequentially: start one worker, inspect aggregate token velocity and write overlap, then admit another only when the remaining budget and independent work justify it.
- Check the aggregate goal counter immediately after each spawn and at every worker boundary; reserve enough allowance for primary reconciliation, validation, plan evidence, and a custody commit.
- Use deterministic tools locally for search, formatting, counters, schema checks, test execution, and other judgment-light work instead of delegating them.

## Hard stops

- No push, merge, install, publication, provider, browser, ingress, or production effect without exact authority.
- Stop for a scope change, an unclassified architectural decision, or exhausted cumulative budget.
- Interrupt worker admission when aggregate consumption reaches 70 percent of the active checkpoint allowance; use the remainder only for reconciliation, validation, plan evidence, and custody.
