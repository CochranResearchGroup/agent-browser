## Finding

Plan 0158 failed to deliver the intended quick, finite defect-discovery result
and an efficient path to reliable client use. It produced useful repairs and
substantial evidence, but preparation, installation, calibration, and new
candidate epochs became the critical path. The three user outcomes remained
incomplete when the operator interrupted execution. This is an execution and
planning failure, not evidence that all of the engineering work was wasted.

The strongest control defect was structural: the historical Work Units section
allowed blocking repair traversals with no numeric stop, while W10 analysis
could not begin until every scheduled case was terminal. Any readiness defect
could therefore add another repair/publication/preparation cycle before the
cross-defect analysis intended to make repair efficient. Later priority
reconciliation explicitly imposed two diagnostic attempts and one repair
verification per failure, superseding unlimited traversal for that sequence.
Those later bounds were an improvement; they did not retroactively make the
campaign converge or remove its unfinished outcome and delivery obligations.

## Why execution failed

### 1. Analysis depended on finishing the machinery it needed to evaluate

**Observed:** the diagnostic objective deferred nonblocking repair, but W6 gated
the substantive tiers, and W10 gated analysis on complete terminal scheduling.
The historical blocking-repair edge had no numeric traversal limit. E3 also
required 54 case/phase IDs across 11 families, a larger undertaking than a quick
defect list. Missing live producers remained after provider-free tooling passed.

**Inference:** the plan optimized for a comprehensive measurement system before
an actionable first inventory. Locally reasonable blockers repeatedly earned
priority over aggregate analysis. The defect was not simply excessive testing;
it was coupling early learning to comprehensive readiness.

**Recommendation:** publish the finite known-defect register immediately; treat
missing producers and untested coverage as gaps. End discovery on its time or
attempt bound with explicit gaps, even if broad calibration is impossible.

### 2. New epochs preserved evidence but did not bound the campaign

**Observed:** failed runs were often retained and candidate identities changed
honestly. Source tests, doctor checks, controlled browser closure, publication,
provider restoration, and fixture rebinding recur in E1. Some repairs improved
infrastructure while the original ordinary-link failures remained.

**Inference:** epoch hygiene prevented evidence erasure but became compatible
with indefinite nonconvergence. Counting checkpoints or calling each blocker
bounded did not bound the sequence of blockers. Later priority limits addressed
individual defects; the report still lacked a compact aggregate outcome view.

**Recommendation:** keep one defect ID across epochs and successor plans. After
two consecutive hardening/preparation checkpoints without advancing one of the
three outcomes, disposition the dependency and change the work selection. Do
not buy another identical cycle by renaming it.

### 3. Authentication proof did not cover runtime attachment

**Observed:** a closed-browser host restart passed, while the later surviving-
browser restart failed through both original handles. The second ledger reports
`Cannot evaluate: target browser session is not running; request a service tab first`.
Its failure is `service_operation_failed`, unknown axis/phase,
`effect_uncertain`, and no executable next action (E4).

**Inference:** separate authorization and retained-attachment paths were not
covered by the earlier acceptance checks. The handoff's source leads suggest
an attachment path mismatch; that implementation cause is not adjudicated here.
Historical identity-unproven failures without effect-time authority evidence
cannot all be called false ACL denials.

**Recommendation:** verify original-handle control with unchanged process,
owner, target, and permissions. Neither broader grants nor replacement tabs
can count as recovery. Attach diagnostic requirements to that same operation.

### 4. Delivery was disconnected from validation

**Observed:** focused repairs advanced source and disposable candidates;
installed P158 and production remained different generations. Production host
availability required a compatibility workaround, not promotion of those fixes.
E1 explicitly excluded production runtime replacement from campaign authority.

**Inference:** withholding an unauthorized deployment was correct. The execution
failure was failing to consolidate a concrete reviewed delivery decision early
enough, so local progress could not produce a user-visible production outcome.

**Recommendation:** review a named repair set, dependencies, production update,
rollback, installed verification, and compatibility-override removal together.
Do not promote the whole development branch because its tests passed.

### 5. Continuation bookkeeping displaced conversational authority

**Observed:** E6 reports execution resumed after questions/interruption and
explicitly rejects treating an old automatic continuation as renewed authority.
At the reviewed baseline, Plan 0158 and ROADMAP still directed further repair.

**Inference:** stale next-action instructions and a persistent unfinished goal
created a route back to execution after the user had changed the task. This is
an agent control error. The user should not have had to repeat the stop.

**Recommendation and enacted correction:** the current plan and roadmap now
record paused execution and the postmortem direction. Historical instructions
remain evidence only. Plan 0159 execution must follow discussion of its concrete
approach; this report supplies no live or implementation authorization.

### 6. Product, harness, infrastructure, and unknown coverage competed in one queue

**Observed:** the first restart failure was a listener readiness race; the
second was a real original-handle failure. W7 mock transport accepted framing
the native ingress did not, and sent an unsupported request field. A supervisor
smoke precreated the directory whose absence broke startup. W had separate
deadline/custody gaps. Missing A04/A06/A12 and generation-transition producers
remained distinct from executed failures (E1, E4, E5).

**Inference:** these different failure classes repeatedly became prerequisites
for the same next run. A green test double could conceal the exact integration
boundary later investigated expensively.

**Recommendation:** classify before selecting work. Fix a harness only when
needed to answer a selected defect's question, using the native boundary when
that is the risk. Unknown coverage creates no automatic experiment queue.

### 7. Evidence presence was confused with evidence sufficiency

**Observed:** a summary hash was retained without the full handoff report W6
required; W partial observations were volatile; full client archive verification
was incomplete. `state.json` alone omitted authoritative owner/lifecycle
sidecars. Zero Service resources did not imply zero ancillary processes.
Historical ready handoffs included deliberately terminal targets (E1, E5, E6).

**Inference:** several claims relied on a projection narrower than the claimed
outcome. Better summaries cannot reconstruct observations that were never
persisted. A stored ready flag or HTTP 200 is insufficient visibility evidence.

**Recommendation:** keep original missing counts unknown, use repository load
semantics, and report Service teardown and process cleanup separately. Require
the report itself when downstream acceptance consumes it. Do not report the
63 historical ready handoffs / 62 absent browser rows as a link failure rate.
