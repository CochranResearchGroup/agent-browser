## Accepted workflow

An application can request a browser on its exact existing Native desktop,
retain Agent Browser profile/automation controls, and open a durable app-ingress
handoff for the original participant and session. Versioned host metadata joins
the task publication transaction. Required placement fails rather than silently
moving to another desktop; preferred placement accepts only listed alternatives.
Continuation and recovery retain the placement constraints. Shared profiles must
satisfy the intersection of their live task constraints.

The reviewed host registry binds an HTTPS application origin and Native consumer
identity. Hosted handoff does not require a standalone Agent Browser public
origin. Callers cannot supply arbitrary redirects. Standalone task identity and
handoff remain unchanged. Hosted operation suppresses Agent Browser pool
maintenance: the application and Native retain assignment ownership.

Compact snapshot/watch output reports recorded task state separately from
unverified browser, viewer, account and controller readiness. Local metadata
changes generate sequenced events without recurring browser or provider queries.
The Bots consumer independently checks current task/session/assignment identity
and mounts the existing Native viewer. Its private dispatch journal holds
uncertain effects without replay. Hosted viewing is read-only; attachment,
sharing and human takeover belong to the dependent tickets.
